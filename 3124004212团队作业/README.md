# 学习任务管家：Python + MCP 智能体课程作业

学习任务管家是一个通过中文文字交互管理学习任务的命令行项目，支持新增、查询、修改、完成任务，以及导出 Markdown 和 CSV 清单。任务使用 SQLite 持久化保存。

项目提供两种运行模式：不需要 API Key 的离线规则模式，以及接入模型 API 的大模型对话模式；工具调用支持本地直连和 MCP 两种通道。

本目录仅保存课程作业源码、自动化测试、配置模板与本说明，不包含博客、演示文档、截图、私人数据库、虚拟环境或真实 API 密钥。

## 2. 环境准备

### 2.1 进入项目目录

下载或克隆仓库后，进入本文件所在的 `study-task-agent` 目录。以下命令均在此目录执行。

### 2.2 选择 Python

需要 **Python 3.10 或更新版本**。Windows 上有多个 Python 时，先检查：

```powershell
py -0p
```

下面以 Python 3.13 为例；请根据本机已安装的版本调整。Python 2.7、3.6 和 3.9 不满足本项目要求。

### 2.3 创建虚拟环境并安装依赖

Windows PowerShell：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

如果启动器未识别某个已安装版本，也可以使用该版本 `python.exe` 的完整路径运行 `-m venv .venv`。

macOS / Linux：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

下文使用 Windows 命令；macOS / Linux 将 `.\.venv\Scripts\python.exe` 替换为 `.venv/bin/python`。直接使用虚拟环境中的解释器，无需激活脚本。

依赖固定为 `mcp==1.26.0`、`pydantic==2.12.5`、`pydantic-settings==2.12.0`。仅运行离线本地模式时，业务程序只依赖 Python 标准库，可以暂不安装第三方依赖；MCP 通道需要安装。

## 3. 正常交互使用

启动：

```powershell
.\.venv\Scripts\python.exe app.py
```

程序启动后，在“你：”提示符后输入一条需求并回车：

```text
添加任务：完成软件工程作业，截止明天，优先级高
添加任务：复习数据库，截止后天，优先级中
查看待办
搜索任务：数据库
查看全部任务
导出全部任务为Markdown
导出全部任务为CSV
退出
```

修改或完成任务时，以程序实际返回的编号为准。例如，目标任务编号为 2 时：

```text
修改任务2：标题改为复习数据库第三章，优先级高
完成任务2
查看已完成任务
```

离线规则模式使用约定句式，支持“今天、明天、后天”和 `YYYY-MM-DD` 日期；可省略截止日期与优先级。输入“帮助”查看格式，输入 `退出`、`exit` 或 `quit` 结束。

仅查询一次也可以运行：

```powershell
.\.venv\Scripts\python.exe app.py --once "查看待办"
```

离线规则解析不等于大模型的开放式语言理解。需要更自由的表达与多轮对话时，按第 5 节接入模型 API。

## 4. MCP 工具通道

安装依赖后，通过 MCP 操作相同的业务工具：

```powershell
.\.venv\Scripts\python.exe app.py --mode demo --transport mcp
```

程序自动启动 `mcp_server.py` 子进程，完成 MCP 初始化、工具发现与工具调用，不需要另开终端运行服务端。

此命令使用离线规则解析输入、通过真实 MCP 执行业务操作。“是否接入大模型”和“是否使用 MCP”是两个不同的配置。

## 5. 接入大模型 API

### 5.1 接口要求

项目已实现模型 API 请求、配置读取、工具结果回传和多轮调用循环。模型服务需要兼容项目使用的 **Chat Completions 格式**，并支持 **`tools` / `tool_calls` 工具调用**。

服务地址与模型名称均可配置，是否兼容某个服务应以其协议与实际调用结果为准。仅支持普通文本生成的接口不能完成本项目的自动工具选择。

### 5.2 创建配置

在本目录打开 PowerShell：

```powershell
if (-not (Test-Path .env)) {
    Copy-Item .env.example .env
}
notepad .env
```

在本机填写以下内容：

```dotenv
LLM_API_KEY=替换为自己的API密钥
LLM_BASE_URL=https://你的服务商域名/v1
LLM_MODEL=替换为实际可用且支持工具调用的模型标识
LLM_TIMEOUT=60
```

| 参数 | 说明 |
| --- | --- |
| `LLM_API_KEY` | 模型接口访问密钥。 |
| `LLM_BASE_URL` | 服务商提供的兼容 API 根地址；程序自动追加 `/chat/completions`。 |
| `LLM_MODEL` | 本人账号实际可用且支持工具调用的模型标识。 |
| `LLM_TIMEOUT` | 单次请求超时秒数，默认 60，允许范围 1～300。 |

示例中的域名和中文文字是占位提示，需要替换。根地址不要包含 `/chat/completions`、账号信息、查询参数或片段。系统环境变量优先于 `.env`。

不要把真实 `.env` 或 API 密钥提交到仓库。`.gitignore` 已排除 `.env`，只保留 `.env.example`。

### 5.3 启动

```powershell
.\.venv\Scripts\python.exe app.py --mode llm
```

大模型模式默认使用 MCP。程序启动后可以尝试：

```text
你好，介绍一下你能帮我做什么。
帮我记一下：明天完成软件工程作业，优先级高。
我有哪些待办？按截止时间列出来。
把刚才的软件工程作业标记完成。
把数据库复习任务的截止日期改到下周五。
把所有任务导出为CSV。
给我一些复习建议，暂时不要创建任务。
退出
```

以上是使用示例，不是已经取得的真实模型实验结果。本次已有功能测试使用离线模式，尚未执行真实模型 API 调用。

模型可直接回复，也可生成工具调用。程序执行后将真实结果回传给模型；涉及数据变更时，可核对 `[工具]`、`[结果]` 和数据库/导出文件。

排查模型接口与 MCP 通信问题时，可以保留模型调用，改为本地工具通道：

```powershell
.\.venv\Scripts\python.exe app.py --mode llm --transport local
```

## 6. 数据保存与导出

默认位置：

```text
data/
├── tasks.db
└── exports/
    ├── tasks_时间_随机标识.md
    └── tasks_时间_随机标识.csv
```

任务编号、标题、截止日期、优先级、状态和时间信息保存在 SQLite。已完成任务仍保留，可通过“查看全部任务”或“查看已完成任务”查询。

指定其他数据目录：

```powershell
.\.venv\Scripts\python.exe app.py --data-dir my_data
.\.venv\Scripts\python.exe app.py --mode llm --data-dir my_data
```

同一个数据目录可以在不同模式间共用。日常使用时保留该目录；需要隔离测试时另选目录。运行生成的数据和文件不包含在本仓库提交中。

| 分类 | 数量 | 覆盖内容 |

| Agent | 10 | 离线流程、工具循环、历史记忆、异常参数、未知工具、重复调用、调用上限与接口失败。 |

## 8. 实现流程与工具

```text
用户中文输入
    ↓
规则解析 / 大模型决策
    ↓
本地工具调用 / MCP 客户端 → MCP 服务端
    ↓
业务参数校验 → SQLite / 文件导出
    ↓
真实结果 → 中文回复（大模型模式会将结果再交给模型）
```

| 工具 | 操作 |
| --- | --- |
| `add_task` | 新增任务，返回真实编号。 |
| `list_tasks` | 按状态、关键词、日期和分页参数查询。 |
| `update_task` | 仅修改指定字段，保留其余字段。 |
| `complete_task` | 标记完成并保留首次完成时间。 |
| `export_tasks` | 导出所有符合状态的任务为 Markdown / CSV。 |

工具使用白名单、参数校验和参数化 SQL。导出文件自动命名，不允许模型指定任意写入路径。Agent 保留最近 10 轮会话，每轮最多进行 6 次模型请求，每次最多 8 个工具调用。

## 9. 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 默认 Python 是 2.7 或旧版本 | 选择 Python 3.10+ 创建虚拟环境，后续使用虚拟环境解释器。 |
| 激活脚本被 PowerShell 限制 | 直接使用本文的 `.\.venv\Scripts\python.exe` 命令，无需激活。 |
| 提示缺少 MCP | 用虚拟环境解释器安装 `requirements.txt`。 |
| 提示未配置模型 | 检查根目录 `.env`，替换密钥与模型占位符，并检查同名环境变量。 |
| HTTP 401 | 检查 API 密钥。 |
| HTTP 400 / 404 | 检查接口根地址、模型标识和工具调用支持情况。 |
| 网络失败或超时 | 检查网络、服务地址和超时设置。 |
| 工具写入后模型请求失败 | 先查询任务状态，已提交记录仍保留，避免盲目重复新增。 |
| 任务编号与预想不同 | 以查询返回的实际编号为准，已有数据库会继续分配新编号。 |

更多运行参数：

```powershell
.\.venv\Scripts\python.exe app.py --help
```

## 10. 项目边界

- 当前为单用户命令行课程项目，没有语音、登录、多用户隔离或定时提醒。
- 任务持久化保存；对话历史仅在当前进程中保留，不跨进程存储。
- 离线模式使用有限规则，真实模型效果取决于实际接口、模型与输入。
- 重复提交新增请求仍可能产生重复任务，尚未实现跨请求幂等。
- 项目初始代码由 ChatGPT 辅助生成，使用者需结合源码、实际运行与测试理解实现。
